# Learning Skills

把孩子的具体学习困难，交给 AI Agent 做成可操作、有针对性反馈的互动专题学习。

当前源码版本：**0.6.1**。统一使用 `interactive-topic-lesson` 入口，内部按语文、数学、英语加载教学指导；交互与局域网交付流程共用。

**0.5新例子**：[平均数能说明什么？](https://b.pluoluo.top/learning-skills/mean-evidence/) 用连续工作台保存构造、修改和解释，没有选择题页。数值条件可核对，文字理由保留为待人工复核；不代表真实孩子学习效果已验证。

**历史样例（v0.1.4）**：下方“周长与面积”演示与截图保留用于回看旧内容，不代表新版三科训练已全面验证。

[DEMO 样例预览](https://b.pluoluo.top/learning-skills/)：以“周长与面积”为例，推荐平板横屏体验，也可以电脑浏览器打开，无需下载或安装 Skill。

![周长与面积互动小课预览](https://github.com/pluoluo/learning-skills/releases/download/v0.1.4/perimeter-area-preview-visible.png)

## 这是什么？

这不是题库，也不是现成课程合集，而是一个给 AI Agent 用的学习 Skill。

你不需要先写教案，也不用准备一套教材。只要把“孩子哪里卡住了”告诉 Agent，它就能围绕这个具体问题生成一节完整的互动小课：

- 一节能直接用浏览器打开的课件，孩子可以点、拖、改、选，不是看讲解视频或做静态题；
- 有具体的操作对象，比如改变图形、替换词语、比较选项，让孩子亲手试；
- 操作后有即时反馈，告诉孩子为什么对、为什么错，而不只是判对错；
- 卡住时可以按需看提示，错了可以重试；
- 学完一个例子，还能换一个新例子再判断一次，看方法能不能用上。

也就是说，你提供“孩子卡在哪里”，Agent 负责把它变成一节可操作、有反馈、能重试的小课。

课程可以围绕数学、语文、英语里的具体问题制作。一个清楚的困惑，就可以作为起点。

## 它解决什么问题？

适合这些场景：

- **概念容易混淆**：比如分不清周长和面积。让孩子改变图形，分别观察“边界长度”和“覆盖大小”。
- **规则会背，换个情境就不会用**：比如知道近义词释义，却不会在句子里选。通过替换、比较和找语境依据来探索。
- **现成材料不贴合眼前问题**：说明孩子已经会什么、停在哪里、想重点观察什么，让课程范围更合适。
- **想让孩子主动尝试**：课程里有可操作的对象、解释原因的反馈、按需提示和重试机会。

比起“数学不好”，更具体地说“会算长方形周长和面积，但看到‘围一圈’和‘铺草地’就选错公式”，Agent 更容易做出合适的小课。

## 怎么用？

推荐流程很简单：

**家长向 Agent 提需求 → Agent 生成并交付课件 → 孩子在平板浏览器里动手探索。**

0.5.1 起，Agent 内部须先规划知识关系、讲解和实际思考任务并审核，再据此规划呈现方式并审核，之后实现 Web，最后分别核对教学实现与浏览器体验。第一轮要能在没有页面的情况下审清教学内容，不能用“动手探索”等活动标题代替实际讲解与材料。审核由 Agent 连续完成，除非用户要求逐轮确认。流程说明见 [authoring-process.md](skills/interactive-topic-lesson/references/authoring-process.md)；新增流程尚未经过真实孩子试用验证，现有公开示例也未按此流程重做。

### 0.5.1 → 0.6 的变化

- 内容审核必答三问：任务能不能答错、最薄弱任务能否靠口诀或试错完成、孩子要获得的新能力是否真的有机会使用。条件已经保证的结论只作演示，不当独立理解证据。
- 呈现审核必须保留完整学生题面、无设计上下文冷读的行动/结果复述、逐条误解与改句、术语和数字情境检查。这是开发自审，不冒称独立教学审核或真实学生验证。
- 新增一页结构模板：[教学计划](skills/interactive-topic-lesson/references/teaching-plan.example.md)、[呈现计划](skills/interactive-topic-lesson/references/presentation-plan.example.md)。呈现模板包含实际冷读发现及退回项，不能抄模板当新课已审核。实现丢条件或提示泄露答案，须修订呈现计划并重审，再验实现。
- 核对反馈先单独一行明确对错，再解释；数值构造注明判断范围，开放解释仍待人工复核。记录、导出、evidenceTasks和可选选择题机制保留。

计划文件只是作者私有输入；0.5.x课件格式、消息协议和review schema不变。旧课件无需补计划即可继续validate/build。现有公开平均数示例的任务仍是历史0.5设计，本次仅调整其反馈，不宣称它已满足0.6内容/冷读要求；完整教学重做另行验收。

开发者可在仓库根目录运行（单独安装Skill时，路径相对于Skill目录）：

```bash
node skills/interactive-topic-lesson/scripts/check-plans.mjs /path/to/private/author
node skills/interactive-topic-lesson/scripts/check-plans.mjs /path/to/private/author --require-approved
node skills/interactive-topic-lesson/scripts/screen-copy.mjs /path/to/private/author/presentation-plan.md --screens s1,s2
node skills/interactive-topic-lesson/scripts/build.mjs /path/to/private/lesson.json --out /path/to/build --require-plans /path/to/private/author
node skills/interactive-topic-lesson/scripts/self-test.mjs
npm test
```

结构检查检查文件、修订号、审核记录和必填项是否存在，不做语义评分，也不校验冷读是否真实执行。字段名及写法见模板；0.6.1支持标签后换行、空行、段落、列表和代码块，空字段与仅注释仍拒绝。合成[合格结构fixture](skills/interactive-topic-lesson/scripts/fixtures/plans/valid)可直接作为检查脚本的目录输入；同目录的missing-review、missing-cold-read和missing-weakest分别演示拒绝与缺项提示。它们只用于测结构，不是假装完成的教学审核。

### 0.6.0 → 0.6.1 的变化

- 冷读明确为实现前硬审；呈现审核增加固定的“答案泄露自检”：可见文字是否包含待填答案或中间结果，是否开局已经给出目标答案，标题是否和目标冲突。数学正确、schema通过和浏览器可操作不能替代它。
- 屏幕原文集中在呈现计划的一个`student-facing-copy` JSON块，含各屏幕状态的标题、题面、按钮、图中标签、状态说明和反馈。冷读和实现核对都由`screen-copy.mjs`抽取这份来源，不再各手写一版；动态渲染仍须用实际浏览器逐屏核对，工具不会自动判断DOM与计划一致。
- 修改后必须二轮重读，可以只抽取改过的屏及跨屏引用，保留实际新发现，控制重复阅读成本。模板保留历史发现，新整理文案标为待补，不冒称已经重读通过。
- 新课最终构建使用`--require-plans 作者目录`，缺项或三项审核结论未明确“通过”时拒绝写文件，并保存私有`plans-check.json`，绑定课件、计划与文案摘要。`--require-approved`可在实现前检查作者声明。默认构建及旧课件兼容方式保留。

这道门槛不监控编辑器，也不能证明画布草稿写在审核之后。回执明确`chronologyVerified:false`；先有画布的偏离仍须在review中如实记录，不能靠回执补写成严格顺序。计划通过也不会自动将最终教学审核或学习效果标为通过。

**旧平台适配提醒**：`evidenceTasks`在lesson根部，**不在special-study.json中**；旧平台仅导入content不会自动获得记录和数值核对能力，需明确实现宿主适配。不可补占位选择题来掩盖能力缺失；见[host-integration.md](skills/interactive-topic-lesson/references/host-integration.md)。

### 1. 让 Agent 安装 Skill

- 把 Skill 链接发给你的 Agent，让它自己安装。
可以直接对 Agent 说：

```
请安装这个 skill：https://github.com/pluoluo/learning-skills。装好后告诉我怎么在新会话里调用它，以及需要我补充哪些信息。
```

- [下载最新仓库源码](https://github.com/pluoluo/learning-skills/archive/refs/heads/main.zip)。技能位于 `skills/interactive-topic-lesson`，让 Agent 按自己的安装方式处理即可。旧版发布包不代表当前源码版本。


你的 Agent 需要能加载 Skill、读写文件、运行脚本。构建工具需要 Node.js 20 或更高版本，环境检查和构建交给 Agent 完成即可。

浏览器操作与截图由 Agent 使用自己的现有工具完成，不要求安装 Playwright，也不要求每次制作课件编写 CDP 检查脚本。Skill 规定需要检查的内容和记录的证据；若当前工具不能操作画布，Agent 应说明未验范围，保留课件，不反复调试底层浏览器连接。附带的 Playwright 执行器仅供已有相应环境时做自动回归。

如果你用的是 Hermes，可以让它把 Skill 放到 `~/.hermes/skills/interactive-topic-lesson`，之后在新会话里使用 `/interactive-topic-lesson`。其他 Agent 按它自己的技能安装方式处理。

### 2. 告诉 Agent：给谁学、学什么、想解决什么

最少说清这三件事就能开始：

- 给几年级或什么基础的孩子学
- 学什么主题
- 现在卡在哪里；不确定也可以说“想先探索一下”

还可以补充：一道错题、孩子的原话、教材片段、希望看到的变化，以及使用偏好，比如“解释短一点”“主要用点选”“不要声音”。默认不限定学习时长；明确的时间偏好只用来调整范围。

可以直接复制这段：

> 使用 interactive-topic-lesson，给四年级、会算长方形周长和面积的孩子做一节互动专题。他看到“围一圈”和“铺草地”时经常选错公式，希望能通过改变图形、观察反馈，理解两种量的区别，并在新例子中判断该量什么。

如果信息不够，Agent 应该先问影响课程的关键问题，并说明它采用了哪些假设。

### 3. 让孩子在平板上打开

默认由 Agent 在学习者所在局域网的电脑或服务上部署课件，最终交付一个同网络平板可打开的网址。可用期限、停止方式和检查状态放在课件的家长说明区，源文件由 Agent 私下维护。

桌面、CLI 或常驻 Agent 均需根据实际环境完成托管。远端 Agent 自己的 localhost 或私网地址未必能被家中平板访问；缺少可达部署环境时，应说明网址交付受阻，而不是把文件路径当作完成交付。安装、端口选择和后续更新都交给 Agent 处理。

孩子优先用平板横屏操作。AI 生成后，建议家长先自己操作一遍，核对知识、图示和答案是否符合预期。

## 你会得到什么？

主要是一个同局域网可打开的课程网址，孩子可以在平板浏览器里操作。默认不向家长交付需要手动编辑的 JSON 或课程文件；需要修改内容时，直接告诉 Agent。

Agent 保留可编辑源、检查报告与部署状态，负责重建并尽量沿用原网址更新。课程不依赖本项目的学习平台账号，操作和学习记录保留在本次页面中；可以主动保存一份可读HTML记录，刷新或关闭后页面内记录清空。记录不会自动上传或跨设备同步。

“本次记录”用于当场回看第一次怎么摆、后来怎么改、用过哪些帮助，也方便家长核对理由。它不是账号学习档案；临时链接失效后，主动保存到本设备的HTML仍可阅读，未保存的页面内记录则不会长期保留。是否保存由学生或家长选择。

主活动使用自由画布组织学习，可以是连续工作台、多场景或其他适合知识点的流程。没有默认六题，也不强制“探索＋检查”两页。补充辨析题可选，奇数题量由布局适应，旧课件继续兼容。训练应覆盖相关易混点，针对具体错选解释，并区分首次检查和看过帮助后的重试。构造、修改和解释可作为本次学习产出保留；播放器分别展示数值条件核对和待人工复核内容，不提供综合掌握分。可选的“辨析核对”只报告给定选项中的识别结果。三科指导也不等于专业教学效果已经验证。

如果试用后发现“这个操作不清楚”“这段解释太长”“换了个例子还是不会”，把具体表现或截图告诉 Agent，让它沿用当前课程继续改。

## 反馈与许可

遇到不好理解的反馈、无法操作的内容，或某个学习问题始终没被解决，欢迎到 [Issues](https://github.com/pluoluo/learning-skills/issues) 反馈。描述你想解决的问题、实际发生了什么、希望怎样改进即可；分享案例时请隐去孩子的个人信息。
