# 先审教学内容，再审呈现，最后审实际课件

用于新课和实质性教学改版。顺序为：知识深度与讲解计划 → 内容审核 → 呈现计划 → 呈现审核 → Web 实现 → 实现后的教学审核与浏览器检查。前一阶段的重大问题未解决，不能进入依赖它的阶段。环境、可达部署和工具检查可以提前做；不能先写一套课件页面再补教学理由。

这是作者的工作顺序，不是孩子必须经历的页面顺序。具体课程可以连续探索、先试后讲、比较改写或采用其他组织方式，不规定题数、页面数、时长和统一的交互模板。

## 1. 写清要理解什么，以及怎样讲清

先在私有作者目录写 teaching-plan.md，标明修订号。读取对应学科指导及 teaching.md、learning-design.md；此时不选择卡片、标签页、拖拽或动效。计划要让审阅者在没有网页的情况下判断教学是否成立，而不只是看到“理解概念、动手探索、深入思考”等标题。

按实际需要记录：

- **起点与边界**：用户原话、学习者已知与假设、本次要改变的理解、必要前置知识、明确暂不处理的范围。补缺与知识整理不必采用同一路径。
- **核心知识关系**：准确结论、成立条件、容易被省略的限制、与相邻概念的联系。深度体现在为什么这样判断、条件变化后会怎样、能用什么例子支持或反驳；不把成人术语、偏题难例或覆盖更多知识当作深度。
- **实际讲解内容**：写出关键解释的学生可见措辞、具体例子和推导/比较依据，说明该解释回应什么困难、何时提供。不能只写“展示原理”“给出提示”。先尝试还是先示范由目标决定；约定性规则如实说明，不为满足“为什么”编造因果。
- **思考任务与材料**：给出真实的题干、文本/数据/图形条件、学习者要作出的判断或产出、可能的合理答案与有吸引力的错误。说明从入门到核心问题究竟增加了什么思考，而不只是换数、换人名。
- **反馈与支架**：针对关键反应，写出具体解释与可行修改方向，区分初次作答、得到帮助和修改。开放表达要写明复核依据及实际提供的支持；只有一个待人工复核的文本框，并不能承担全部讲解与反馈。
- **新情境及证据**：给出适合本课目标的迁移任务或其他可辨认的变化，说明它能观察到什么、不能观察到什么。任务不必成为选择题，也不必全自动评分。

这些是教学决策，不是每项固定一段、每课固定几道题的表格。保留必要的完整材料与反馈，使别人能复查结论，避免用冗长泛论代替具体设计。

## 2. 第一轮只审内容，不替页面找理由

重新从目标、实际材料和可能反应出发审阅，记录在 teaching-plan.md 的审核部分：审阅方式、对应修订、具体问题、修改、复核依据和剩余限制。默认由作者另做一次自审；可用且已获授权的独立审阅可以补充，但不是安装或完成 Skill 的前提，不冒称独立审核。

审核重点：

- 核心关系和讲解是否正确，范围是否适合该学习者；每个关键解释是否有实际例子/依据，是否隐含未经确认的前置知识。
- 学生能否仅凭一个关键词、照着示范替换或反复试错完成所有任务；若能，原本要求的理解在哪里发生？找出最薄弱的任务并说明其不足。
- 选取核心任务，实际写出一个合适反应和一个有代表性的不充分反应，按计划走一遍解释、反馈和修改。不能以“这里会给针对性反馈”代替反馈内容。
- 新情境改变了什么关系或判断条件；如果只验证熟练度，应如实缩小目标，不能声称已覆盖迁移或深度理解。

发现知识错误、关键讲解缺失、目标与任务不对应、核心思考可被捷径跳过，或反馈无法支持修订时，退回修改。只在内容已达到本次目标且重大问题已解决后记录“可进入呈现设计”。此结论不等于真实学习效果验证。需要外部来源核实时遵循环境的资料检索要求，记录真正看过的材料；不得虚构教材依据。

例如英语第三人称单数：只列“he/she/it + s，拖词填空，再做六题”不足以通过内容审核。需要明确本课范围，说明在具体语境里怎样确定主语所指、怎样表达日常行为，以及学生如何在主语改变时保留意思并修改句子。可用 `Mia plays after school` 与 `Mia and Leo play after school` 检查“看见人名就加 s”的局限，并解释变化依据。是否加入否定句、特殊变化或更多句式由本课目标与基础决定，不把所有规则都塞进一课。这是一个内容设计例子，不是所有英语课的固定任务。

## 3. 再决定怎样让学生看见、操作与思考

基于已通过内容审核的修订写 presentation-plan.md。引用 teaching-plan 的修订号；用文字场景、简图或简短分镜即可，无需先做成 Web。把每个关键知识关系/任务映射到：

- 学生最初实际看见的材料与指令；哪些信息已给出，哪些仍需要自己找出或组织。
- 可以修改、构造、比较或表达的对象，以及操作前后的真实变化/不变量。
- 何时看到什么反馈、讲解和帮助；一条典型错误怎样得到支持并被修改。
- 需要保留的作品和理由、可核对的条件及需人工复核部分，依据 learning-evidence.md 选择实际支持的方式。
- 核心对象、操作和反馈在宿主实际高度预算内怎样呈现；较长材料怎样展开或滚动，而不删去教学所需内容。

选择交互必须说明它如何帮助观察本课关系。例如拖动应使一个有关的变化可观察；如果只是把四个备选答案从点击改成拖动，不能因此声称增加了思考。没有可自动评分的条件也不能把原任务偷偷降成选择题。

在同一文件记录呈现审核：用第一轮相同的实际任务和反应走查，确认呈现没有替学生完成判断、提前泄露要预测的答案、删除关键条件，或把复杂操作负担误当知识深度。查看错误反馈、帮助展开和新情境，不能只审首页构图。重大问题解决后记录“可进入 Web 实现”。若技术能力无法承载核心教学要求，回到计划修订并说明损失，不能以美观或实现方便通过审核。

## 4. 实现后重新检查教学是否真的发生

将审过的材料、任务与反馈实现到 lesson.source.json 和 canvas.html。源文件中的 objectives/learningDesign 是实现映射，不替代前两轮内容审核。

完成后分开检查：

1. **教学实现**：对照两个计划的具体修订，查看实际显示的解释、核心任务、关键错误反馈与新情境。实际走一遍合适反应和不充分反应，检查是否被按钮、标题、默认值、自动提示或评分逻辑绕过了应有的思考。静态正确的答案不代表互动承载了原设计。
2. **浏览器与界面**：使用现有浏览器工具检查可操作性、触控/键盘、宿主高度、展开、反馈、恢复和来回调整视口。按 browser-check.md 记录观察；截图和脚本通过不能代替第1项。
3. **边界与效果**：说明尚未观察到的能力；没有真实学习者试用，就不声称已经证明深入浅出或学习有效。家长试用后提供的具体反应应反馈到相应计划。

将实际教学检查依据写入私有 review.json 的 subject.evidence：计划修订、学科指导、检查的具体任务、发现和修复的问题及未验证范围。审过计划不会自动让最终 subject 变成 passed；只运行校验则保持 not_run。现有校验器只检查结构与报告形式，不机器判定教学深度或强制这些语义审核，不能把形式通过说成内容审核通过。

修改知识结论、学习目标、材料、讲解或评价依据时，回到内容计划；只改变呈现但影响信息可见性、支架或证据时，重审呈现并检查是否牵动内容；纯样式/实现修复复用未受影响的计划并做相称检查。内容或课件更新后不能沿用旧修订的审核结论。重大问题经现有两轮修订仍未解决时，保留私有草稿并说明阻碍，不靠补写“已审核”交付。

默认由 Agent 连续推进这些工作，不要求家长逐轮审批。用户明确要求先看方案或某轮确认时，交付该阶段可读的具体结果并按要求等待；不把内部作者文件变成默认家长作业。
